# PanelForge image revision showcase

Mounted once in the existing PanelForge case at `#image-revision`, after case navigation and before starting-point prose. No new route, lab, client script, generation endpoint, or remote resource is introduced.

The native radio group switches the actual image visibility through CSS. The default shows both images; phones stack them, while wider screens place them alongside each other. Original and Revision each show one image at full available width. Native arrow keys, touch labels, and evidence disclosures work without JavaScript. Labels are at least 46px tall; body copy and captions are at least 14px.

Public media is limited to these five files:

- `original.jpg` and `revision.jpg`: exact downloaded actual generated bytes.
- `gallery-detail.png`: real gallery detail with the retained-original relationship, cropped below account navigation.
- `completed-chat.png`: actual reference attachment, instruction and completed result; opaque personal-avatar cover.
- `receipt.json`: explicit reference equality checks, exact JPEG hashes, two completion records, returned costs and scope notes. Source job/conversation/message IDs and URLs remain private.

The source illustration and one revision were generated specifically for this controlled demonstration. The original file matches before and after the edit. Composition preservation between the two generated outputs is a qualitative judgment. The jobs used separate conversations connected by image lineage. Screenshots review completed generations.

`source-provenance.json` records the method and boundaries. `media-provenance.fragment.json` is the five-entry fragment for the shared public manifest and reviewed-media allowlist; it is source material and is not a second public manifest.

Validation: `tests/browser/image-revision.spec.ts` checks native keyboard/focus, 390/768/1440 geometry and axe, touch, no JavaScript, exact public asset hashes and receipt equality, static GET-only traffic, and exclusive mounting in the existing PanelForge case. The existing PanelForge viewport checks in `portfolio.spec.ts` also pass.
